1. How to Use This Guide
This guide provides the complete Spanish-language content specification for all 8 /es/ pages. These pages mirror the structure, layout, and design of their English counterparts exactly — the only differences are the translated text content, the URL paths, and the hreflang tags.
For layout specifications, design tokens, CSS properties, image specs, and component behavior, refer to the corresponding English developer guide. This document provides ONLY the translated content and technical implementation details specific to the Spanish pages.
Translation Approach
All translations are written in natural, conversational Latin American Spanish appropriate for Chicago’s predominantly Mexican and Central American Hispanic population.
Translations are culturally adapted, not word-for-word. Marketing copy is rewritten for natural Spanish, not mechanically translated.
Technical terms and brand names remain in English: "Cents app," "Spin It Up Laundry," "EBT," "Google Maps."
Phone numbers, addresses, and pricing remain identical to the English pages.
The client should have a native Spanish speaker review all translations before publication. The translations in this guide are professional-quality but should be verified for regional accuracy.

2. Technical Implementation
2.1 hreflang Tags
Every English page must include hreflang tags pointing to its Spanish counterpart, and every Spanish page must include hreflang tags pointing to its English counterpart. Both pages also need a self-referencing hreflang tag.

Example for the Homepage:
<!-- On / (English homepage) -->
<link rel="alternate" hreflang="en" href="https://spinituplaundry.net/" />
<link rel="alternate" hreflang="es" href="https://spinituplaundry.net/es/" />
<link rel="alternate" hreflang="x-default" href="https://spinituplaundry.net/" />
 
<!-- On /es/ (Spanish homepage) -->
<link rel="alternate" hreflang="en" href="https://spinituplaundry.net/" />
<link rel="alternate" hreflang="es" href="https://spinituplaundry.net/es/" />
<link rel="alternate" hreflang="x-default" href="https://spinituplaundry.net/" />

DEV ACTION:  Every page pair (English + Spanish) must have reciprocal hreflang tags. x-default points to the English version. The hreflang tags go in the <head> of BOTH pages. Missing or non-reciprocal hreflang tags will cause Google to ignore them entirely.
2.2 HTML lang Attribute
All Spanish pages: <html lang="es">. All English pages remain <html lang="en">.
2.3 Canonical URLs
Each Spanish page has its own canonical URL (self-referencing). The canonical of /es/ is /es/, NOT /. Spanish pages are NOT duplicates of English pages — they are alternate-language versions.
2.4 XML Sitemap
Add all 8 Spanish pages to the XML sitemap with the same priority as their English counterparts. Optionally, use the sitemap xhtml:link element to declare hreflang relationships in the sitemap itself (in addition to the <head> tags).
2.5 Language Switcher
Add a language toggle to the site header (both English and Spanish versions). Design spec:
Location: right side of header, before the phone number / CTA button.
Format: "EN | ES" text toggle. Active language bolded. Inactive language is a link to the current page’s counterpart.
Font: 14px/600, color Caption Gray (#64748B). Active: Dark Slate (#0F172A), weight 700.
Mobile: same toggle, positioned in the hamburger menu header area.
Each toggle link points to the equivalent page in the other language (e.g., /services/ → /es/servicios/ and vice versa).
2.6 JSON-LD Schema
Spanish pages use the same schema types as their English counterparts. The "name" and "description" fields are translated to Spanish. The "inLanguage" property should be set to "es" on Article schemas. All other structured data (address, phone, coordinates, pricing) remains identical.
